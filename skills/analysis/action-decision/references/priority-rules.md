# 优先级规则

## 排序维度

| 维度 | 含义 | 数据缺失时 |
| --- | --- | --- |
| 价值（value_score） | 客户/机会的价值量级 | 不排序或按已知维度排序并声明 |
| 意愿（demand_event） | 触发事件与需求信号 | 声明未使用 |
| 可触达（channel_reach） | 渠道可用性与历史响应 | 声明未使用 |
| 排除惩罚（disturbance_penalty） | 免打扰、频次、投诉史 | 未接入则整体降级 |

## 分档

- 按综合分分档：高（≥80）/ 中（60~79）/ 低（40~59）/ 不推送（<40，含被排除客户）。
- 分档阈值是**未校准的排序假设**：必须标注 `HYPOTHESIS`，不得声称"转化率更高"。
- 分档输出的是**人数**（每档多少人），不是客户明细。

## 排序纪律

1. 规则过滤先于评分：被适当性或免打扰规则排除的客户不进入评分（不是扣分）。
2. 分数构成（weights）必须可复算：权重之和为 1，每一项的来源事实登记在 `derived_from`。
3. 缺维度的客户单独成组"信息不足"，不并入低分档——低分和缺分是两回事。

## 输出形态

```
优先级分布：高 {fact:xx} / 中 {fact:xx} / 低 {fact:xx} / 信息不足 {fact:xx}
```

（所有人数都必须是服务端事实；没有事实时只描述排序方法，不给分布数字。）
