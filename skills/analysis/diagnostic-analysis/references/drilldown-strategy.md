# 下钻策略

差异找到后，回答「集中在谁身上」。下钻是逐层的：每层只在数据允许时进行，每层下钻都要保持两侧可比。

## 常用下钻维度（按优先级）

1. **资产层级** `aum_tier`：差异是否集中在高/低资产段——最常见的混杂因素。
2. **风险等级** `risk_level`：产品持有差异常与风险承受能力共线。
3. **客户等级** `customer_tier`：存量经营分层。
4. **机构** `org_branch`：地域经营差异。
5. **时间**：差异是结构性的还是本期事件驱动的。

## 方法

- 逐层计算「客群值 vs 基准值」的差异，观察差异在哪个子群放大。
- 子群样本低于抑制阈值（20）时该格必须抑制（`SUPPRESSED` / 图上 `value: null`），不得展示。
- 下钻层数控制在 2~3 层：更深的层通常样本不足，结论会失去统计意义。
- 记录每次下钻的过滤条件，保证结论可复算。

## 收敛判断

- 差异在某个子群显著放大 → 「差异主要集中于……」，这是可下结论的形态。
- 差异在各子群均匀 → 说明差异与这些维度无关，换维度或接受"未定位到集中方向"。
- 数据不足以完成下钻 → 在 `reasons` 与 `boundary` 写明缺哪一层的什么数据。

## 与事实层的关系

下钻产生的新数字同样是事实：要么来自确定性数据系统，要么登记为 MISSING。下钻中临时口算的结果不得写进报告——比率、差值必须由服务端事实承载。
