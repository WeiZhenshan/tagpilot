# 指标目录（Metric Catalog）

事实分析按下面五组规划「理论上应该看什么」。目录中标注「已接入」的才是可用事实；其余在输出中登记为 `MISSING` 事实与边界说明。

标注「选标签可取」的指标：只要用户在左侧标签栏选择了对应标签，服务端就会把它作为 `tag_stats` 注入，可以直接写成事实——数值列给人数/缺失/最小/最大/合计/均值/中位数，分类列给取值分布与占比。同一标签没有选择时，仍然登记为 MISSING，并在 `followups` 里建议补充选择；不要因为"应该能取到"就写出数字。

## 口径说明

- 金额单位默认「元」，不要把万元/亿元等复合单位写进 `unit`。`tag_stats` 里的数值已由服务端按标签语义层登记的量纲折算好（万元量纲折成元、比率折成百分数），直接引用即可，不要再做换算。
- 占比类指标（`%`）在平台契约里必须带分母（`denominator_id`），没有分母不得生成占比事实。分布条目已带 `share`，直接引用即可。
- 分布类指标在图上最多展示 12 个类别；超过时选择业务关键类别并说明截断范围，不允许编造「其他」桶。
- `tag_stats` 里 `plan_tag=true` 的列已经被圈选条件截断（例如条件是「AUM ≥ 50 万」，AUM 的均值就只覆盖 50 万以上客户），必须在卡片边界里说明这一点。
- `unit` 为 `null` 的标签没有登记单位，它的数字不能写成事实；只能定性描述并登记 MISSING 说明单位缺口。
- 标注「未接入」的指标，本轮统一登记 `MISSING` 事实（挑与本问题最相关的 3~6 个），并在边界中说明缺失对结论的影响。
