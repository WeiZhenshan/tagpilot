# 降级与不配图

## 判定顺序

对每张候选图按顺序检查，第一个不通过就执行对应降级：

1. **有事实吗？** 相关指标全部 MISSING → 不画，正文说明缺口。
2. **事实可用吗？** 事实 AVAILABLE 但 `sample_size` <20（或人数 <20）→ 该格抑制；若整张图都抑制 → 不画。
3. **类别/系列超限吗？** >12 类别或 >8 系列 → 截断并说明，或改 table。
4. **能对账吗？** 构成/漏斗类对不上账 → 降级为 table 或删图。
5. **意图清楚吗？** 说不清"这张图想表达什么" → 不画。

## 各意图的典型降级

| 场景 | 处理 |
| --- | --- |
| 只有一个数据点 | kpi；若连 kpi 都不合适（如类别名不明确）→ 不画 |
| 有一个 AVAILABLE 人数 + 一堆 MISSING | 只画 KPI（人数），其余在正文声明缺失 |
| 分布数据有抑制格子 | 保留抑制占位（`value: null`），整图仍可画 |
| 全部的类别都被抑制（样本小） | 不画 |
| 比例缺分母 | 不画占比图；改绝对量或删 |
| 漏斗某层缺失 | 不画漏斗 |

## 输出契约

- 可画：产出 spec（经 chart-atomic），并说明每张图"表达什么 + 有什么未展示"。
- 不画：`charts` 为 `[]`，在 `reasons` 与正文里写明**为什么不出图**（数据缺失/样本不足/无法对账），并给出补齐路径（followups）。

## 为什么宁缺毋滥

图表比文字更容易被当成结论。一张建立在缺失数据上的图，会让读者忽略正文里的边界声明。平台上"本次不配图 + 说明原因"是合格产出，"勉强的图"是不合格产出。
