# 图表组合层

一次分析的多张图不是并列的，而是一条**阅读主线**。组合层决定：出几张、什么顺序、谁是主图。

## 工作步骤

1. 收集本轮已有的图表 spec（来自 chart-intent / chart-atomic）与它们的意图。
2. 按 `references/dashboard-layout.md` 选版式（概览 / 诊断 / 行动），并按信息顺序排序。
3. 去重与裁剪：同一意图、同一数据的图只留一张；总图数按 `references/storytelling.md` 的规则控制。
4. 输出：**有序的图表清单**（按最终顺序列出各图 id + 一句话角色），供分析技能放进 `insight-result` 的 `charts` 数组。

## 组合原则

- **一篇一条主线**：先给结论性数字（KPI），再给支撑（对比/结构），最后给可行动对象（明细/漏斗）。读者从上往下读，逻辑不回头。
- **少而精**：每张图必须能回答"它在主线里承担什么";承担不了就删。
- **顺序即阅读顺序**：平台按 `charts` 数组顺序渲染（KPI 类单独置顶成行），不要依赖随机摆放。

## 版式与图数的对应

| 版式 | 适用 | 典型结构 | 图数 |
| --- | --- | --- | --- |
| 概览 | 客群是什么样 | KPI 规模 → 分布/构成 | 2~4 |
| 诊断 | 哪里异常、为什么 | KPI 差异 → 对比条形 → 下钻矩阵 | 2~5 |
| 行动 | 接下来做什么 | KPI 对象数 → 漏斗 → 明细 | 2~4 |

单张图（含单 KPI）说明不需要组合层，直接输出即可。
