# 数据故事规则

## 每张图的角色声明

组合时给每张图写一句话角色（不进入 spec，进入分析正文的说明）：

```
chart-scale：本客群的规模底数
chart-tier：规模按资产层的分布，回答"集中在哪一档"
```

写不出角色的图，删。

## 去重规则

- 同一份数据、同一意图 → 只保留表达力强的一张（一般是有序列/可对读的那张）。
- `table` 与图形表达同一数据时，只在"需要精确读数"时保留 table。
- KPI 与同数据的条形图并存没有意义——KPI 用于一个数，条形用于多类比较。

## 图数上限

- 单个分析结果建议 ≤6 张图（不含 KPI 行）。更多说明主线不清，先回退去重再裁剪。
- 平台层面的硬上限是 30（契约限制），但那是防御性上限，不是目标。

## 叙事与图的关系

- 正文写"论点"，图给"证据"：正文提到差异时，差异图紧随其后。
- 图题用业务语，主图可以用问句（"产品覆盖集中在哪一档？"）——问句图题引导读者带着问题看图。
- 任何图都必须能被正文引用（正文里说明它在讲什么）；正文没提到的图，要么补正文引用，要么删图。

## 边界

组合层不新增数据、不改 spec 内容（那是 chart-atomic 的职责）、不改变事实表。发现某张图与主线无关时，删图而不是改数据。
