# 编码规则

## 单位（unit）

| unit | 用途 | 注意 |
| --- | --- | --- |
| `人` | 客户数、触达数 | 整数；0 或 ≥20（抑制阈值）才允许展示 |
| `元` | 金额 | 保持原始数值，不换算单位（不写"万元"） |
| `%` | 占比 | 必须有分母事实（`denominator_id`）；值域 0~100 |
| `pp` | 百分点差 | 差异类指标（客群值 − 基准值） |
| `分` | 评分、点数 | 评分类事实 |

一张图的 `unit` 是单一的；混合单位的表达拆图。

## 方向（orientation）

- `horizontal`：类别名较长（中文机构名、产品名）或多于 6 个类别时的默认选择——横向条更好读。
- `vertical`：类别少且名称短，或强调序列（如时间）时使用。
- 该字段对所有 kind 都必须填写（`kpi`/`table` 也填 `vertical`）。

## 系列（series）与格子（points）

- 每个系列：`{ name(≤24字), fact_ids[], points[] }`；`fact_ids` 必须与格子里的 `fact_id` 一一对应（集合相等）。
- 每个格子：`{ category(≤24), column, fact_id, value }`。
  - 非矩阵图（非 heatmap）`column` 必须为 `null`。
  - heatmap 的 `column` 是第二维（≤24 字）。
- 同一系列内 `(category, column)` 不能重复。
- 类别去重后总数 ≤12；列去重后 ≤12。超过时截断——选择业务最关键的类别，并在说明里写明还有多少类别未展示。
- 事实值缺失（MISSING/SUPPRESSED）的格子：`value: null`，事实侧 `sample_size: null`。

## 标题与标识

- `id`：`^[a-z][a-z0-9_.-]{0,79}$`（如 `chart-holding-rate`），用于引用与导出文件名。
- `title` ≤80 字；`metric_label` ≤40 字；用业务语言（「产品持有率」而不是「rate_1」）。

## 对账（reconcile）

对账是图表可信度的锚：读者能验证"这部分加起来等于整体"。

| kind | 何时必须 | 规则 |
| --- | --- | --- |
| `sum` | 展示组成且各格可加 | `fact_ids` 之和 === `total_fact_id` 事实值（tolerance ≤0.05） |
| `percentage` | 占比堆叠（unit=%） | 每类别一条，`fact_ids` 为该类别全部格子，合计 100±tolerance |
| `funnel` | 漏斗图 | `fact_ids` **与展示顺序完全一致**，且逐格单调不增 |

不满足对账时优先修正数据选择（舍弃不可加的格子），而不是硬凑。

## 标注（annotations）

- 最多 8 条；`text` ≤500 字，其中**任何阿拉伯/全角数字都必须写成 `{fact:id}` 占位**（守卫会检查占位之外没有数字），`fact_ids` 声明本标注引用的全部事实。
- 标注用于指出拐点、阈值线或口径提示（如「口径：近30天」——注意"30"是数字，需改写为「口径：近一月」或改用事实占位）。

## 零基线

`zero_baseline` 恒为 `true`：柱状与漏斗从 0 起，避免视觉夸大；这是平台统一的诚实性要求。
