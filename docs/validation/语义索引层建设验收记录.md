# 语义层与索引层建设验收记录

日期：2026-09-19。对照 `docs/design/标签语义层与检索索引建设方案.md`。本记录只验收本地可运行演示、业务语义、检索评测、权限与反馈闭环；生产环境、容量、备份、监控和运维决策不在本次范围。

## 结论

**本地演示链路已达到 ACTIVE，但尚不能宣称达到银行人工终验或“真实大模型已连接”。**

已完成的硬事实是：969/969 业务标签与 177 个码值字段、1723 个码值已按 `AI_EXPERT_LOCAL_DEMO` 模式批量复核并落为 `REVIEWED`；新快照 `L107-20260919-002` 已发布，真实 BGE-M3 + bge-reranker-v2-m3 已在 Milvus 建立 969 全库索引，600 题本地封存集的点估计指标通过，快照和索引已激活为 `ACTIVE`。Chrome 实测完成 Java → Python/LangGraph → Milvus → DSL → Java 反馈入库闭环。

仍需人工补充的关键事实是：当前 `REVIEWED` 的复核人是 AI 业务专家演示身份，`human_bank_signoff=false`；600 题由当前已复核快照构造，不是独立第三方 Gold；Agent 已接入 LangGraph 和 OpenAI-compatible 选择器接口，但本次未配置受批准的生成式模型端点，页面明确显示 `model_connected=false`。

## 已完成的建设

### 1. 全量语义复核与发布门禁

- 来源冻结为 970 字段，其中 1 个对象键 `CUST_ID` 不进入业务检索，正式分母为 969。
- 969 条标签语义、177 个码值字段、1723 条码值语义均进入 `REVIEWED`；同时形成 682 个可发布概念、5470 条已复核别名。
- 全量复核中补充 988 条别名、修正 491 条语义类型或单位，将 5 个跨域混合概念拆分为 11 个域内概念。
- Java 发布门禁结果：`coverage=969/969`、`excluded=[]`、完整度均分 94、最低 70、`publishable=true`。“黄金业务场景”尚没有由银行人员指定独立清单，因此不用全库均分 94 代替其“单标签≥90”的人工验收。
- 完整度 70/90/85 只是质量门禁，不能抵消码义错误、来源失效或人工签署缺失。

### 3. LangGraph Agent、DSL 与反馈闭环

- Agent 固定流程为 `retrieve → select → validate → finalize`；只能看到 Java 传入的当前角色可用、已发布标签候选。
- `AudienceQueryDSL` 对标签资格、允许操作符和已发布码值做确定性校验；结果一律 `auto_execute=false`，合法 DSL 也必须人工确认。
- 已提供 OpenAI-compatible 大模型选择器适配；未配置端点时仅允许“唯一已复核精确证据”的离线选择，其他情况返回澄清或候选，不假装已连接 LLM。
- Chrome/admin 实测查询“上月借记卡消费金额至少0”，返回标签 1175“上月借记卡消费金额”，页面显示快照/构建、`DSL=合法，待确认`、`selector=exact-evidence-offline`、`大模型已连接=否`。
- 在同一页点击“符合需求”后，Java 按本人 Trace 将 `ACCEPT`、推荐标签 1175 和最终标签 1175 写入 `ts_retrieval_feedback`，单次更新行数为 1。

### 4. 真实角色权限

- 已从当前数据库读取 13 个用户的真实角色与语义权限；`admin/ry/wzs` 具有各自现有权限，QA 范围角色、无角色、停用角色和停用用户不会因数据范围而继承语义权限。
- 真实 Spring AOP 方法门禁已验证：有权角色 `list=ALLOW`，无权角色 `list=DENY`且 `publish=DENY`。
- 当前可见的顺畅浏览器闭环使用 admin；非管理员账号的实际登录页面矩阵仍需业务验收人按期望权限签字。

## 达到最终高质量目标仍需人工补充

1. **银行业务签署。** 个人客户经营条线指定复核人，逐项或按有审批依据的受控批次确认 969 标签及 177/1723 码义，重点审核 491 条自动类型/单位修正、金额元/万元、比例 0..1、复合口径、机构码名义语义和每标签至少 3 条别名。签署后把 `human_bank_signoff` 置为 true，留存复核人、时间、依据和变更摘要。
2. **黄金场景名单。** 由业务人员指定黄金标签/场景清单，逐标验收完整度≥90；当前只能证明全库最低 70、均分 94（已超过均分 85 目标）。
3. **真正独立的 600 题 Gold。** 由未参与语义生成/调优的人员独立编写、复核和封存，外部保管 SHA-256；增加码值覆盖、多条件、hard negative、澄清、不可表达和不同角色资格。再在当前固定 build 上运行，报告分母、失败题 ID、点估计及置信区间。
4. **真实生成式 LLM 连接。** 指定已批准的本地或 OpenAI-compatible 端点、模型名和凭据注入方式，明确可以发送的标签元数据范围。确认页面 `model_connected=true`后，重跑独立 Gold 及幻觉/越权/DSL 契约集；不能用当前精确证据回退模式冒充大模型结果。
5. **非管理员验收签字。** 选取有权经营人员、无权人员、停用角色各一个实际登录，对查询、发布、资格剪裁和本人 Trace 反馈做页面/HTTP 签字。
6. **最终 ACTIVE 批准。** 上述 1–5 完成后，在新的人工签署快照上重建索引、重跑独立 Gold，再由有权审批人确认激活。当前 `ACTIVE` 仅表示本地演示链路已打通。
