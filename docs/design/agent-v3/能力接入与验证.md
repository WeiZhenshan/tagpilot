# Agent V3 能力接入与验证

## 已实现的边界

原方案 schema_version=2 仍编译为旧规则 schemaVersion=3；新方案为 schema_version=3，包含 intent_plan 和条件 tree，编译为规则 schemaVersion=4。两种版本号属于不同契约，不可混用。新规则保存 audiencePlan，所有保存、SQL预览、人数统计、样例与再次运行均通过 RuleTagValidator 重建物理表达式。JSON 中 authorityValidated 无法设置服务端信任标记。

意图的原始要求、AND/OR 关系及执行节点的 requirement_ids 分离。一个业务要求可展开多个执行节点，但每个节点只能归属一个要求；组合计算放进该要求的表达式。修改业务条件建立新版本。此机制能检出结构遗漏/逻辑变化，不能证明模型对所有自然语言的解释均正确。

技术诊断先进入有界修复；业务选择才 interrupt。预算为每请求 12–36 次工具调用、默认 240 秒、每条件 6 次标签检索、3 轮内部修复、最多 2 轮 Java 权威反馈修复。相同证据 3 次无进展结束为保留草案；时间预算在节点边界检查，正在进行的单次 HTTP 调用受自身超时控制。缓存固定到 build、资格集和工具参数，不跨请求共享。

目前计算白名单：TAG、CONST、ADD、SUB、MUL、DIV、COUNT_POSITIVE、CAPABILITY。DIV 的分母非正返回未知；NULL 传播；COUNT_POSITIVE 重复输入拒绝。不同时间输入必须显式跨期并提供各自口径。排序、排名、分段 CASE、任意日期函数、多表 JOIN、窗口函数均未开放。

聚合模板是固定数据集版本上的客户关联聚合：COUNT_DISTINCT / COUNT / SUM / MAX / MIN / AVG，固定过滤项最多 12 个，同源数据库，只能引用启用的字段别名。模板不接受用户任意 SQL 或动态字段。缺失值不作为零；零事件需 FULL 覆盖声明。过滤窗是发布模板的一部分，不能把固定日期伪装为自动滚动窗口。多层聚合、基金按产品合并后求最大占比，需要先提供治理后的客户-产品数据集或客户级指标。

## 能力记录流程

1. 先应用新增的前向迁移 V20260921_04（本次交付不自动迁移任何数据库）。
2. 通过 POST `/taglibrary/semantic/capabilities/{libraryId}` 保存草案，需现有语义编辑权限与库可见性。
3. 通过 POST `/taglibrary/semantic/capabilities/{libraryId}/{id}/{version}/review` 复核，需语义复核权限。复核是业务责任，不由本实现自动代签。
4. 使用现有发布快照/构建/激活流程。每个 capability_id 只导出最高已复核版本。旧快照与旧索引保持不可变。
5. `/capabilities` 按固定 build 返回模型可见定义、依赖与业务模板，隐去物理 implementation，并裁剪不在资格集内的能力。Java 每次执行检查最新发布版本及数据集 ONLINE 版本。

必填字段：capability_id、正整数 version、capability_type、name、definition、applicability、source_ref、input_tag_ids。计算能力另需 unit、grain=CUSTOMER、implementation。业务定义需 plan_template。aliases 是字符串数组。复核后的版本不能原地编辑，以新版本演进。能力记录表是设计期持久层，不是自然语言会话记忆。

以下仅为**结构模板**，占位符须替换为真实已治理标识，不能直接提交：

## 实施与回退

按数据库迁移 → Java/语义/Agent 服务 → 工作台的兼容顺序升级。在新快照包含 capability 行之前，先更新语义服务，否则旧加载器会拒绝新行。不要在现有库执行全量初始化 SQL。

`tag.agent.expressions-enabled=false` 可阻止新版规则执行；旧 schema_version=2 保持原路径。已有 V4 客群继续保留原方案，不能降级为旧版并删除计算条件。旧 Vue 编辑器对 V4 只允许查看/统计/预览，修改请回原智能体会话；服务端仍重新核验。旧版本不可变快照的哈希保持兼容；能力行中的有序参数参与哈希。

## 验证层次

- `expression-contract.json`：Python 与 Java 共用的合成契约样本，验证表达式和口径门禁。
- Agent 单测：真实 LangGraph + SQLite 检查点，模型/检索替身；覆盖修复、预算、重启恢复、权限收紧与结构保护。
- Java 单测：受控编译、SQL结构、信任标记防伪及既有业务回归；不代表 MySQL 实算。
- React 单测/Playwright：合成接口数据，仅验证交互、草案禁执行与移动端。
- `tagpilot-agent/scripts/evaluate_workbench.py`：明确指定工件的真实模型只读冒烟；读取已发布检索服务；能力检索运行本地当前代码；资格使用快照标签，**并非 Java 当前用户资格**。不统计/建群，不能据此宣称端到端业务验收。
- `案例能力矩阵.md`：61 条逐项路径与缺口，目标人数不是执行结果。

后续完整验收须使用独立审核样本、当前用户权限、Java编译与模拟库实算，验证结果 ID 集及人数、否定/NULL/时间边界、多轮修改和恢复，不得只比较模型的 valid 标记。全部61条和969标签业务覆盖均未由本次小样本证明。
