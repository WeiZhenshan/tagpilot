# 数据代理模块-数据源管理开发文档

## 1. 背景与目标

当前标签系统已在 MySQL 中导入一张标签宽表，需要建设数据代理模块的数据源管理能力，集中管理来自数据库的数据源，支持配置连接信息、可视化展示数据表与视图，并统一采集和管理元数据。

参考图中的数据源为 StarRocks，本系统第一阶段以 MySQL 等价替代。不同数据源按不同 MySQL database 理解，即一个数据源配置对应一个目标 MySQL database。

本功能要求作为独立业务模块落地在 `ruoyi-databroker` 文件夹中，但暂不作为独立应用启动。`ruoyi-databroker` 只作为 Maven 业务 jar 模块，由 `ruoyi-admin` 引入并随主应用同进程启动。整体采用“前后端分离 + 单体后端多模块 + MVC 分层”的架构。

## 2. 应用架构

### 2.1 总体形态

```text
ruoyi-ui
  |
  |  /dev-api
  |
  v
ruoyi-admin  :8080
  原 RuoYi 管理服务，负责登录、菜单、用户、角色、权限
  依赖 ruoyi-databroker，统一提供 /databroker/** 接口

ruoyi-databroker
  独立业务模块目录，负责数据源配置、元数据采集、表/字段展示
  |
  |  业务配置库
  v
MySQL ry                   保存 sys_* 权限表与 dp_* 数据代理业务表

ruoyi-admin 同进程中的 ruoyi-databroker 业务代码
  |
  |  独立 JDBC 连接，仅用于采集 information_schema
  v
目标 MySQL database         标签宽表所在库；不同 database 即不同数据源
```

### 2.2 服务内部架构

`ruoyi-databroker` 模块内部采用 Spring MVC + Service + MyBatis Mapper 分层架构。

```text
Controller
  接收 HTTP 请求、权限校验、参数校验、统一返回 AjaxResult/TableDataInfo

Service
  编排数据源保存、测试连接、同步元数据、中文名维护、操作日志写入

Mapper + XML
  读写 dp_* 管理表

metadata
  通过独立 JDBC 连接目标 database，读取 information_schema

crypto
  数据源密码可逆加密、解密、脱敏
```

### 2.3 认证与权限

`ruoyi-databroker` 不单独启动，直接复用 `ruoyi-admin` 进程中的 RuoYi JWT、Redis 登录态、`@PreAuthorize` 和权限表达式。

要求：

- 前端登录仍走 `ruoyi-admin`。
- 前端请求 `/databroker/**` 时继续携带 `Authorization: Bearer <token>`。
- `ruoyi-admin` 统一完成 JWT 过滤、Redis 登录态读取和权限校验。
- `ruoyi-databroker` 的 Controller 仍使用 `@PreAuthorize("@ss.hasPermi('databroker:datasource:list')")`。

## 3. Maven 模块调整

### 3.1 根 pom.xml

在根 `pom.xml` 的 `<modules>` 中新增：

```xml
<module>ruoyi-databroker</module>
```

建议在 `dependencyManagement` 中补充声明，便于后续其他模块引用：

```xml
<dependency>
    <groupId>com.ruoyi</groupId>
    <artifactId>ruoyi-databroker</artifactId>
    <version>${ruoyi.version}</version>
```

```xml
<!-- 数据代理模块 -->
```

## 5. 配置接入

`ruoyi-databroker` 不提供独立 `application.yml` 和启动类。配置统一写入 `ruoyi-admin/src/main/resources/application.yml`，数据库连接继续使用 `ruoyi-admin/src/main/resources/application-druid.yml`。

### 5.1 application.yml

在 `ruoyi-admin/src/main/resources/application.yml` 增加数据代理专用配置：

```yaml
xss:
  enabled: true
  excludes:
  urlPatterns: /system/*,/monitor/*,/tool/*,/databroker/*

databroker:
  crypto:
    secret: ${DATABROKER_CRYPTO_SECRET:change-me-32-bytes-secret-key}
  jdbc:
    connectTimeout: 5000
    socketTimeout: 10000
```

### 5.2 application-druid.yml

无需为 `ruoyi-databroker` 单独创建 `application-druid.yml`。数据代理管理表 `dp_*` 与 RuoYi `sys_*` 表同库，直接使用 `ruoyi-admin` 的主数据源配置。

要求：

- 目标标签库不写入 Druid 主数据源配置。
- 目标标签库通过业务表 `dp_datasource` 的连接信息动态创建 JDBC 连接。

## 8. 后端接口设计

接口统一前缀为 `/databroker`。

### 8.1 目录树与数据源树

```text
GET /databroker/datasource/tree
权限：databroker:datasource:list
返回：目录 + 数据源混合树
```

返回节点示例：

```json
{
  "id": "ds_100",
  "parentId": "cat_10",
  "label": "tag_wide_table数据源",
  "nodeType": "datasource",
  "datasourceId": 100,
  "catalogId": 10,
  "sourceType": "MYSQL",
  "status": "0",
  "children": []
}
```

### 8.2 数据源 CRUD

```text
GET    /databroker/datasource/{id}
POST   /databroker/datasource
PUT    /databroker/datasource
DELETE /databroker/datasource/{ids}
```

权限：

- 查询：`databroker:datasource:query`
- 新增：`databroker:datasource:add`
- 修改：`databroker:datasource:edit`
- 删除：`databroker:datasource:remove`

新增请求：

```json
{
  "catalogId": 10,
  "sourceName": "标签宽表数据源",
  "sourceType": "MYSQL",
  "host": "127.0.0.1",
  "port": 3306,
  "databaseName": "tag_db",
  "username": "tag_user",
  "password": "plain-password-on-request-only",
  "usePool": "0",
  "useSsl": "0",
  "caCert": "",
  "jdbcParams": "{}",
  "remark": "标签宽表库"
}
```

返回详情时：

- 不返回 `passwordCipher`。
- `password` 固定返回 `******` 或不返回。
- `caCert` 可返回，但日志中不记录全文。

修改时：

- `password` 为空或 `******` 表示不修改原密码。
- `password` 为其他值时重新加密保存。

### 8.3 测试连接

```text
POST /databroker/datasource/test
权限：databroker:datasource:test
```

用于新增表单和编辑表单中的“测试连接”。请求体与数据源表单一致。

成功返回：

```json
{
  "code": 200,
  "msg": "连接成功",
  "data": {
    "dbVersion": "8.0.36",
    "databaseName": "tag_db"
  }
}
```

失败返回：

```json
{
  "code": 500,
  "msg": "连接失败：Access denied for user"
}
```

### 8.4 同步元数据

```text
POST /databroker/datasource/{id}/sync
权限：databroker:datasource:sync
```

同步逻辑：

1. 查询数据源配置。
2. 解密密码。
3. 使用独立 JDBC 连接目标 database。
4. 查询 `select version()` 更新 `db_version`。
5. 查询 `information_schema.tables` 采集表和视图。
6. 查询 `information_schema.columns` 采集字段。
7. 查询 `information_schema.KEY_COLUMN_USAGE` 采集外键。
8. 使用 `sync_batch_no` 做本批次标记。
9. 新对象插入，已有对象更新。
10. `cn_name` 只在为空时用 `table_comment` 初始化，不覆盖人工维护值。
11. 本批次不存在的表标记 `status = '1'`。
12. 写入同步操作日志。

返回：

```json
{
  "code": 200,
  "msg": "同步成功",
  "data": {
    "tableCount": 12,
    "viewCount": 2,
    "columnCount": 186,
    "syncBatchNo": "SYNC20260705143000123"
  }
}
```

### 8.5 表信息

```text
GET /databroker/datasource/{id}/tables
权限：databroker:datasource:list
参数：pageNum, pageSize, objectName, objectType
```

返回表格列：

- `objectName`：表/视图名称
- `objectType`：`TABLE` 或 `VIEW`
- `cnName`：中文名
- `usageCount`：使用量
- `columnCount`：字段数
- `updateTime`：最近同步时间

### 8.6 字段信息

```text
GET /databroker/datasource/table/{tableId}/columns
权限：databroker:datasource:query
```

返回：

- 序号：`ordinalPosition`
- 字段名：`columnName`
- 类型：`columnType`
- 备注：`columnComment`
- 主键：`isPk`
- 外键：`isFk`

### 8.7 修改中文名

```text
PUT /databroker/datasource/table/{tableId}/cnName
权限：databroker:datasource:edit
```

请求：

```json
{
  "cnName": "客户标签宽表"
}
```

规则：

- 最长 30 个汉字或 60 个字符。
- 允许为空。
- 修改后写操作日志，日志类型 `CN_NAME`。

### 8.8 操作记录

```text
GET /databroker/datasource/{id}/logs
权限：databroker:datasource:query
参数：pageNum, pageSize, logType, result
```

日志类型：

```text
INSERT    新增
UPDATE    修改
DELETE    删除
TEST      测试连接
SYNC      同步元数据
CN_NAME   修改中文名
```

日志详情必须脱敏：

- `password`
- `passwordCipher`
- `caCert`
- 其他密钥类字段

## 9. 元数据采集 SQL

### 9.1 表与视图

```sql
select
  table_name,
  table_type,
  table_comment,
  table_rows,
  create_time,
  update_time
from information_schema.tables
where table_schema = ?
  and table_type in ('BASE TABLE', 'VIEW')
order by table_name;
```

映射规则：

```text
BASE TABLE -> TABLE -> 表
VIEW       -> VIEW  -> 视图
```

### 9.2 字段

```sql
select
  table_name,
  column_name,
  ordinal_position,
  column_type,
  data_type,
  is_nullable,
  column_default,
  column_comment,
  column_key
from information_schema.columns
where table_schema = ?
order by table_name, ordinal_position;
```

映射规则：

```text
is_nullable = 'NO' -> isNullable = '0'
is_nullable = 'YES' -> isNullable = '1'
column_key = 'PRI' -> isPk = '1'
其他 -> isPk = '0'
```

### 9.3 外键

```sql
select
  table_name,
  column_name,
  referenced_table_name,
  referenced_column_name
from information_schema.KEY_COLUMN_USAGE
where table_schema = ?
  and referenced_table_name is not null;
```

## 10. 密码加密与脱敏

数据源密码必须可逆加密保存，不能使用 `SecurityUtils.encryptPassword`。该方法是 BCrypt 哈希，无法解密，不能用于 JDBC 连接。

实现要求：

- 新增 `DataBrokerCryptoService`。
- 使用 AES/GCM/NoPadding。
- 密钥来自 `databroker.crypto.secret`。
- 保存时只保存密文到 `password_cipher`。
- 读取连接时在服务端解密。
- 接口返回和操作日志永远不出现明文密码。
- 日志记录请求快照前必须统一调用脱敏方法。

脱敏字段名：

```text
password
passwordCipher
caCert
secret
token
key
```

## 12. 业务规则

### 12.1 数据源唯一性

同一未删除状态下，`source_name` 唯一。

### 12.2 删除规则

删除数据源时执行逻辑删除：

- `dp_datasource.del_flag = '2'`
- 关联表元数据可保留，状态置为失效
- 操作日志保留

### 12.3 同步覆盖规则

- 同步可更新字段类型、字段备注、主键、外键、字段顺序。
- 同步不覆盖人工维护的 `cn_name`。
- 同步后已不存在的表置为 `status = '1'`。
- 同步后已不存在的字段可删除，也可按批次标记失效；第一阶段建议删除字段记录，避免字段弹窗展示历史脏数据。

### 12.4 连接测试规则

- 新增和编辑表单均可测试连接。
- 测试连接成功不自动保存表单。
- 已保存数据源同步前先测试连接。
- 测试失败写失败日志。

### 12.5 连接池规则

第一阶段 `use_pool` 字段保留，但默认不启用持久连接池。每次测试或同步创建短生命周期 JDBC 连接，用完关闭。

原因：

- 数据源数量不确定。
- 第一阶段只采集元数据，不执行高频查询。
- 可避免动态连接池生命周期管理复杂度。

## 15. 验收标准

1. `ruoyi-admin` 在 8080 正常启动，并已加载 `ruoyi-databroker` 模块。
2. 前端登录仍走原 RuoYi 登录页。
3. 登录后访问数据源管理页面，请求 `/dev-api/databroker/**` 能自动携带 token。
4. `/databroker/**` 接口由 `ruoyi-admin` 提供，不需要单独启动数据代理服务。
5. 未授权用户无法访问 `databroker:datasource:*` 受控接口。
6. 能新增一个指向当前 MySQL database 的数据源。
7. 测试连接成功后能返回数据库版本。
8. 点击同步元数据后，能看到已导入的标签宽表。
9. 表信息页能正确统计表数量和视图数量。
10. 字段信息弹窗能展示字段名、类型、备注、主键、外键。
11. 中文名可编辑，且重新同步后不被覆盖。
12. 操作记录能展示新增、修改、测试连接、同步、中文名修改。

14. `mvn clean package -pl ruoyi-admin -am -DskipTests` 通过。
15. `npm run build:prod` 通过。

注意：当前仓库没有真实测试用例，`mvn test` 通过不代表功能已验证。验收时必须启动 `ruoyi-admin` 和前端页面，手工执行新增、测试连接、同步、字段弹窗、权限拦截流程。

## 16. 非目标范围

第一阶段不实现以下能力：

- 不支持 StarRocks 专用协议。
- 不支持 PostgreSQL、Oracle、SQL Server。
- 不做真实数据查询代理。
- 不做跨库 SQL 执行。
- 不做标签宽表内容预览。
- 不引入注册中心、网关、配置中心。
- 不把目标 database 注册为 Spring 动态数据源。

这些能力可在数据源管理稳定后，按数据代理模块后续版本单独设计。
