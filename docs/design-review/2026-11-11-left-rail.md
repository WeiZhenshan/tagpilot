# TagPilot 智能体工作台 · 左栏与顶栏交互反馈评审

日期：2026-11-11
范围：`tagpilot-assistant` 顶栏与左侧历史/标签栏（含左分隔条），只评操作感知与视觉反馈，不评功能正确性

## 一、现象总述

用户的感受是准确的，而且可以被源码解释成一个结构性事实：**这套界面只有两层反馈——静态默认态和 0.15s 的背景色变化。** 全模块 CSS 中 `:active` 只出现在两处（都在分隔条上，`index.css:1529`、`index.css:1551`）；其余所有按钮——顶栏返回、左右栏开合、新建、会话项、标签、chip 删除、账户、菜单项——按下时唯一的视觉变化就是背景色从 `#fff`/`transparent` 过渡到 `#f0f2f5`，没有任何缩放、位移、加深或状态保持。按下动作在视觉上等同于"悬停了一下"。

`DESIGN.md` 把这种扁平视为立场（Motion 段：只有面板 200ms 短位移；Elevation 段：没有 `box-shadow`；Buttons 段：悬停只改背景、没有位移动画）。但"扁平"针对的是装饰，不是反馈。一个控件从"可点"变成"被点中"所需要的信息，本来就不是投影，而是：按下时的形变、点击后的状态停留、拖拽过程中的持续信号。当前设计把这三件事一起删掉了，所以用户得到的是"我点了一个贴纸"。更麻烦的是，源码里还存在几处"点击后什么都不会发生"的静默路径（见 L-02），以及"悬停反而像取消选中"的级联冲突（L-03），这些已经超出风格问题，属于可用性缺陷。

另有一处与 `DESIGN.md` 的事实冲突需要先点出：文档写"当前界面没有 `box-shadow`"，但 `index.css:166` 的库下拉（`.library-options`）已经有 `0 8px 24px rgba(38,51,69,.12)`，`index.css:867` 的回到最新按钮也有阴影。也就是说"零投影"并非严格执行的规则，而是碰巧漏在了需要的地方之外——账户菜单（`index.css:578`）就没有。这反而给了本次优化一个不需要推翻文档的切口：**投影只用于"脱离文档流的浮层"，反馈用形变与状态色。**

## 三、发现清单

### P0 — 用户明确感知"点了没反应"

**L-01 全局没有按下态（pressed state），这是"没有操作感"的第一根因**
`index.css:32-44` 给 `button` 定义了 `transition: background 0.15s` 与 hover 背景；全文件搜索 `:active` 只命中 `index.css:1529` 和 `index.css:1551`（都属分隔条）。因此顶栏返回、侧栏开合、新建、会话项、置顶/归档/删除、标签 chip、账户、菜单项在 pointerdown 到 pointerup 之间没有任何区别于 hover 的表现。
建议：给全局加一条按下规则并限定作用域（详见第四节 A），按下 90ms 内必须出现 ≥1px 位移或 ≥1.5% 缩放。

**L-02 pending 期间点击会话项静默失败，且没有任何禁用视觉**
`App.tsx:424-438` 的 `operation()` 在 `inflight.current` 为真时直接 `return false`；`App.tsx:761-779` 的会话按钮只设了 `aria-disabled={pending}`，而 `index.css:417-426` 没有任何 `[aria-disabled="true"]` 样式。用户看到的按钮与平时完全一致，点下去——没有加载、没有变灰、没有提示，世界安静。这正是"点击任何东西都没有我做了操作的感觉"最字面的版本。
建议：补 `.history-select[aria-disabled="true"]` 的 `opacity: .55; cursor: progress;`，并让顶栏状态位同时进入"正在保存…"（见 L-13）。

### P1 — 反馈弱或不一致

**L-03 悬停选中会话会让它"变浅、像被取消选中"**
`index.css:42-44` 的 `button:hover:not(:disabled) { background: #f0f2f5 }` 特异性为 (0,2,1)，高于 `.history-select { background: transparent }` 的 (0,1,0)，所以会话按钮的 hover 背景实际会绘制在 `.history-item.selected` 的 `#e8ecf2`（`index.css:450`）之上。`#f0f2f5` 比 `#e8ecf2` 更亮，悬停当前项时选中感反而被抹掉。
建议：`.history-item.selected .history-select:hover { background: #dfe6ef }`（加深而非变浅），或在选中项上用 2px accent 内嵌左边条替代纯底色。

**L-04 侧栏开合：按钮没有展开态，面板位移太小，最后一帧整块跳**
- `.sidebar-toggle` / `.report-panel-toggle` 在 `aria-expanded="true"` 时没有任何样式（`index.css:116-124`），用户无法从按钮本身判断侧栏是开还是关。
- `panel-motion.css:8` 的位移是 `clamp(12px, 6%, 32px)`，224px 栏只有约 13px，视觉上接近纯淡出。
- 桌面收起靠 `.sidebar-collapsed .history-rail { display: none }`（`index.css:1352-1356`）触发，`allow-discrete` 会在 120ms 退出动画结束后才释放布局——也就是说先淡出 120ms，再一帧收回 224px，中栏内容整体左跳。

建议：给展开按钮加 `background: #eef2f7` 的展开态；位移距离提到 `clamp(16px, 8%, 36px)`；给中栏内容在布局回收时加 `transition: none`（保持瞬切，但让淡出与布局回收同时开始——把 `display` 过渡时长改为与 opacity 同步即可，或改为宽度过渡 180ms + opacity）。后者需要改 `panel-motion.css` 与 `index.css` 的协作，建议作为独立小改动验证。

**L-05 分隔条拖拽全程没有"正在拖拽"的强化信号，也没有宽度读数**
`SplitHandle.tsx:40-52`：按下只给 `document.body` 加 `split-resizing` 类并设置 pointer capture；`index.css:1554-1561` 里这个类只做 `cursor: col-resize` 与 `user-select: none`。`.split-handle:active::before`（`index.css:1529`）与 hover 完全同款（3px `#9aa7b8`）。拖 100px 时，手柄自身唯一的反馈是"线本来就是粗的"。另外 `App.tsx:905-911` 传给 `SplitHandle` 的 `width` 在拖拽期间不更新（`previewSplit` 只写 DOM 变量，`App.tsx:120-122`），所以 `aria-valuenow`（`SplitHandle.tsx:36`）在拖拽中是过期值。
建议：拖拽中用 accent 色加粗线（`body.split-resizing .split-handle::before { background: var(--accent) }`），grip 变成 accent 色实心胶囊，并在手柄顶部浮出等宽数字宽度徽标（`224 px`，`tabular-nums`）；把 preview 宽度提到 state（rAF 节流）以同步 `aria-valuenow`。

**L-06 标签树的展开/收起是"瞬移"**
`TagTree.tsx:64` 用 inline `style={{ transform: open ? "rotate(90deg)" : undefined }}` 换角度，CSS 中没有给这个 svg 定义 transition，箭头瞬间翻转；`TagTree.tsx:74` 直接 `render(node.children)` 挂载/卸载子树，没有任何进出场；`.tag-tree-row:hover`（`index.css:381`)也没有 transition。展开一个大目录时，画面是一块内容凭空出现。
建议：箭头 `transition: transform 160ms var(--ease-standard)`；子树的第一层加 140ms 的 `opacity + translateY(-2px)` 进入动画（`@starting-style` 或 keyframes，并自带 reduced-motion 兜底，见 L-18）；行 hover 加 `transition: background 120ms`。

**L-07 账户菜单"啪"地出现，且比同级浮层更平**
`index.css:578-588` 的 `.account-menu` 无 `box-shadow`、无动画、`z-index: 8`；同一个界面里的库下拉 `.library-options`（`index.css:153-167`）有 8px 扩散阴影，滚动到底按钮（`index.css:867`）也有。菜单是典型的"脱离文档流的浮层"，缺阴影+缺动画让它看起来像页面上贴了一张白纸。同时 `ChevronIcon`（`ListboxSelect.tsx:5-16`）用换 `path d` 的方式表达开合，两张路径直接替换，没有旋转过程。
建议：`.account-menu` 加 `--elev-2` 阴影 + `transform-origin: bottom left` + 180ms 的 `opacity/translateY(6px)/scale(.98)` 进入；账户按钮的 chevron 改为固定向下路径 + `rotate(180deg)` 过渡（这同时改善所有使用 `ChevronIcon` 的下拉）。

**L-08 历史列表没有加载态，先展示"你的圈选任务会保存在这里"再跳出列表**
`App.tsx:838-846` 只判断 `visibleHistory.length`，没有 loading 分支；`reloadHistory`（`App.tsx:283-285`）是异步的，首屏或切换"最近/已归档"时列表为空，空态文案先闪一下，随后条目突然出现。空态文案是"你的圈选任务会保存在这里"，在被误读为"没有数据"之外，还会造成一次布局跳动。
建议：增加 `historyLoading` 状态，加载中渲染 2–3 条骨架行（`index.css:520` 附近），或在空态位置显示"正在读取会话…"；切换归档时保留上一份列表并降低透明度，直到新数据返回。

**L-09 分隔条的键盘焦点用浅灰底代替焦点环，违反本模块自己的焦点约定**
`index.css:1515` 给 `.split-handle` 设了 `outline: none`，`:focus-visible` 只给 `background: #eef2f7`（`index.css:1534-1536`）。这是一个 9px 宽、几乎不可见的浅灰条，且 `DESIGN.md` 明确要求控件焦点为主题色 2px 外轮廓、偏移 3px（`DESIGN.md:195`）。键盘用户 Tab 到分隔条时基本不知道自己在哪里。
建议：`:focus-visible` 用 `box-shadow: 0 0 0 2px var(--accent)` 或恢复 outline；保留背景作为辅助。

### P2 — 细节

**L-10 rail-tabs 选中态瞬时切换**（`index.css:370-372`）：选中项只换白色底和字重，没有指示器或滑动胶囊；两个 tab 之间切换时视觉上像闪烁。建议给选中项 `box-shadow: var(--elev-1)` + 180ms 的背景过渡，或在 `.rail-tabs` 上做一条可平移的 2px 下划线指示器。

**L-11 新建按钮 hover 变灰反而像失活**（`index.css:327-332`）：白卡在浅灰栏上靠"更白"突出，hover 却把它压成 `#f0f2f5`，比栏底色还暗，观感从"可按"变成"不可按"。建议 hover 用 `#f7f8fa` + `--elev-1`，按下 `translateY(1px)`。

**L-12 会话/标签搜索框的焦点样式与全站控件割裂**（`index.css:333-339` 与 `50-57`）：一个只有下划线的输入框，聚焦时出现 2px accent、偏移 3px 的完整矩形 outline，像在文字下面套了个框。建议这类"下划线输入"单独用 `border-bottom-color: var(--accent)` + `box-shadow: 0 1px 0 var(--accent)`，保留可访问对比度。

**L-13 顶栏状态只有字符串替换**（`App.tsx:669-675`，`index.css:304-308`）：`正在保存…` 与 `准备就绪` 之间没有任何过渡，也没有随状态变化的标记。由于 `role="status"` 已经正确设置，可以在视觉上补一个 6px accent 圆点做 `opacity` 呼吸（900ms，reduced-motion 下静止），让"系统正在做事"可被余光捕捉。

**L-14 触控目标偏小**：顶栏图标按钮 padding 7px + 18px 图标 = 32×32（`index.css:116-124`），chip 删除按钮 24×24（`index.css:399`）。桌面可接受，移动端（该栏在 ≤760px 会变成覆盖面板）低于 44×44 的通行建议。建议在 `@media (pointer: coarse)` 下把二者提到 40–44px。

**L-15 双击重置宽度是隐藏功能**（`SplitHandle.tsx:55`）：唯一的提示是 `title`（悬停约 1 秒后才出现），双击后没有确认反馈，也没有"已恢复默认"的短暂提示。建议重置时在宽度徽标位置短暂显示"默认宽度"并淡出 800ms。

**L-16 空状态只有一行灰字**（`index.css:520-524`）：左侧栏大面积留白处只有"你的圈选任务会保存在这里"，没有指向"新建圈选"的动作暗示。建议空态下方放一个与主按钮同款的次级操作按钮，或直接把空态做成"开始你的第一次圈选 →"的可点击行。

**L-17 分页在本次实现中不存在**：评审清单里的"分页"无对应代码——`App.tsx:286-289` 的 `visibleHistory` 是对全量 `history` 的过滤，没有分页或虚拟列表。列表变长后缺少"已到底"的边界反馈，滚动条是唯一线索。若后续引入分页，建议加载更多按钮带 120ms 的骨架过渡，并保持滚动位置。

**L-18 `prefers-reduced-motion` 只禁 transition，不禁 animation**：`index.css:1477-1482` 的全局兜底是 `* { transition: none !important }`，`panel-motion.css:48-54` 也只处理 transition；现有的 `run-*` 动画是逐条手动关闭的（`index.css:1189-1193`）。本次建议新增的菜单 pop、树节点进入、状态呼吸都基于 `animation`，必须各自补 `@media (prefers-reduced-motion: reduce) { animation: none !important }`，否则会在减少动态模式下反而成为唯一还在动的东西。

## 四、左栏交互反馈优化建议（含具体数值）

### A. 先立三层 token（不新增第二套基础 token，并入 `index.css: :root`）

```css
:root {
  /* 时长：按下 < 悬停 < 浮层，全部 ≤ 220ms */
  --dur-press: 90ms;
  --dur-hover: 150ms;
  --dur-state: 180ms;
  --dur-pop: 180ms;
  --ease-standard: cubic-bezier(0.2, 0.8, 0.2, 1);
  --ease-pop: cubic-bezier(0.16, 1, 0.3, 1);   /* 复用 panel-motion 的入场曲线 */

  /* 高度：只给脱离文档流的浮层，普通面板继续零投影 */
  --elev-1: 0 1px 2px rgb(23 36 58 / 6%), 0 1px 1px rgb(23 36 58 / 4%);
  --elev-2: 0 8px 24px rgb(23 36 58 / 12%), 0 2px 6px rgb(23 36 58 / 6%);
  --elev-drag: 0 2px 8px rgb(23 36 58 / 14%);
}
```

对应 `DESIGN.md` 的修订只需一句话：**"零投影"改为"普通内容面零投影；浮层（下拉、菜单、拖拽读数）使用 elevation-1/2"**——这本来就已是 `index.css:166` 的既成事实。

### B. 按下态：全局一条规则 + 列表项例外

```css
button:not(:disabled) {
  transition: background var(--dur-hover) var(--ease-standard),
              transform var(--dur-press) var(--ease-standard),
              box-shadow var(--dur-hover) var(--ease-standard);
}
button:not(:disabled):active {
  transform: translateY(1px) scale(0.985);
}
/* 图标按钮用更明显的收缩，文字列表项禁止缩放以免文字抖动 */
.back-button:active, .sidebar-toggle:active,
.history-actions button:active, .chip-remove:active, .tag-expand:active {
  transform: scale(0.92);
}
.history-select:active { transform: none; background: #e3e8ef; }
```

按下反馈必须在 `--dur-press` 内完成，抬起后 150ms 回到默认；这条规则覆盖了顶栏、新建、标签、账户、菜单的全部控件，是本报告性价比最高的一项。

### C. 逐个组件

**顶栏**
```css
.sidebar-toggle[aria-expanded="true"] { background: #eef2f7; color: #24272c; }
.back-button:hover, .sidebar-toggle:hover { background: #f0f2f5; color: #24272c; } /* 已有底，补 icon 变深 */
.topbar-status[data-pending="true"]::before {          /* 需在 App.tsx 加 data-pending */
  content: ""; display: inline-block; width: 6px; height: 6px; margin-right: 7px;
  border-radius: 50%; background: var(--accent);
  animation: status-pulse 900ms ease-in-out infinite;
}
```

## 五、与整体设计语言的关系

"简洁白灰"约束的是配色与装饰密度，不是反馈通道。这套界面真正需要补的是**状态层**（按下、选中、拖拽中、加载中）与**浮层层**（菜单、拖拽读数），而不是给所有面板加投影。用形变承担"我按到了"、用状态色承担"我选中了"、用 elevation 只承担"我离开了纸面"——这样既保留了 DESIGN.md 的无装饰立场，也能让用户第一次觉得"这个工作台知道我在做什么"。
