# TagPilot 智能体工作台 · 交互反馈设计优化方案（汇总）

- 日期：2026-11-11

- 实施状态：批次 0–1 已落地（2026-11-11，含 `e2e/interaction-feedback.spec.ts` 覆盖）；批次 2–4 待实施

## 一、总诊断

用户的感受是准确的，而且三份评审指向同一个结构性事实：

> **这套界面只定义了"静止"和"悬停"两种状态。按下、提交、等待、完成、拖拽中——这些"用户正在改变状态"的瞬间，全部没有视觉表达。**

证据（已复核）：

| 事实 | 位置 |
|---|---|
| 全仓库唯二的 `:active` 规则都在分隔条上 | `src/index.css:1529`、`src/index.css:1551` |
| `button` 只有 `transition: background 0.15s` + hover 变灰，无位移/缩放/阴影变化 | `src/index.css:32-49` |
| 发送链路先清空输入框，再串行 `createThread` → `startRun`，成功后才 `setThread` | `@assistant-ui/.../base-composer-runtime-core.js:150`、`src/App.tsx:467-484` |
| `pending` 期间会话项只设 `aria-disabled`，没有任何禁用样式，点击被 `operation()` 静默 `return` | `src/App.tsx:424-439`、`src/App.tsx:763` |
| `DESIGN.md` 声称"当前界面没有 box-shadow"，但代码已有 3 处 | `src/index.css:166`、`867`、`795` |

所以"平面化"不是缺装饰，而是缺**状态**。需要补的是四类状态，而不是给所有面板加投影：

1. **按下（pressed）**——"我按到了"
2. **进行中（pending/loading）**——"它在处理"
3. **结构变化（transition）**——"变化从哪来、到哪去"
4. **拖拽中（dragging）**——"我正在调整"

对应四条病因，按影响面排序：

- **A. 全局层**：所有按钮按下 = 悬停；全局 `button:hover` 特异性还会污染局部组件（选中项悬停变浅、运行记录标题出现整行直角灰带）。
- **B. 链路层**：异步操作只有"禁用"没有"进行中"。发送、统计、创建、保存核验、反馈，全部是"点完变灰，然后世界安静 1~数秒"。这是体感上最接近用户原话"点了没反应"的一类。
- **C. 结构层**：tab 内容、条件编辑区、创建确认区、运行记录、菜单、图表、消息、横幅，全部是条件渲染裸 mount。变化没有起点和终点，视觉上就是"啪"地出现/消失。右栏切 tab 还附带一次宽度跳变（370px → `clamp(370px, 44vw, 620px)`），整个三栏重排。
- **D. 深度层**：输入器、右栏、浮层与白底几乎同色同面，"可操作物体"和"背景纸面"分不开。

## 二、统一设计语言 v2：状态层

原则一句话：

> **静止与常规悬停保持扁平；只有"用户操作后 ≤1s 内发生的变化"（按下、焦点、提交、状态流转、浮层出现）允许 ≤220ms 的形变、阴影与颜色过渡。**

这既保留 `DESIGN.md` 的克制，又把反馈从"颜色一条通道"扩展到"形变 + 状态色 + 有限阴影"三条通道。

### 2.1 Token（并入 `index.css :root` / `panel-motion.css`，不建第二套基础 token）

```css
:root {
  /* 时长：按下 < 悬停 < 状态 < 面板，全部 ≤ 220ms */
  --duration-press: 90ms;
  --duration-fast:  120ms;
  --duration-base:  180ms;
  --duration-panel: 220ms;

  /* 缓动 */
  --ease-standard: cubic-bezier(0.2, 0, 0, 1);      /* 状态变化 */
  --ease-enter:    cubic-bezier(0.16, 1, 0.3, 1);   /* 复用 panel-motion 入场曲线 */
  --ease-exit:     cubic-bezier(0.4, 0, 1, 1);

  /* 层级：只给"浮起来的东西"，静态内容面继续零投影 */
  --elevation-1: 0 1px 2px rgb(23 36 58 / 6%), 0 1px 1px rgb(23 36 58 / 4%);
  --elevation-2: 0 8px 24px rgb(23 36 58 / 12%), 0 2px 6px rgb(23 36 58 / 6%);  /* 即 library-options 现值 */
  --elevation-3: 0 18px 44px rgb(23 36 58 / 16%);
}
```

elevation 落点（其余一律无阴影）：

| 层级 | 用途 |
|---|---|
| `--elevation-1` | Composer 输入器、吸顶区块、拖拽读数、选中 tab |
| `--elevation-2` | 所有下拉/菜单/技能菜单/历史版本弹层 |
| `--elevation-3` | 对话框、移动端覆盖面板 |

### 2.2 全局按下态（一条规则覆盖 80% 投诉）

```css
button:not(:disabled) {
  transition:
    background var(--duration-fast) var(--ease-standard),
    border-color var(--duration-fast) var(--ease-standard),
    color var(--duration-fast) var(--ease-standard),
    box-shadow var(--duration-fast) var(--ease-standard),
    transform var(--duration-press) var(--ease-standard);
}
button:not(:disabled):active {
  transform: translateY(1px) scale(0.985);
}
/* 例外 1：整行元素只下沉不缩放，避免文字抖动 */
.history-select:active,
.run-heading:active,
.run-entry-toggle:active,
.library-option:active { transform: translateY(1px); }
/* 例外 2：图标按钮给更明确的收缩 */
.back-button:active, .sidebar-toggle:active,
.history-actions button:active, .chip-remove:active,
.tag-expand:active { transform: scale(0.92); }
```

同时修掉全局 hover 污染：整行元素补局部圆角 hover，选中项悬停用**加深**色而不是变浅。

### 2.3 进行中状态语言

- 按钮：加载时替换文案（`统计中…` / `创建中…` / `核验中…` / `提交中…`）+ 12px spinner，固定 `min-width` 防抖动，`aria-busy="true"`。
- 发送链路：乐观气泡。`onNew` 开头立即渲染一条半透明"你 · 发送中"消息，成功与真实消息位置重合后移除，失败淡出 120ms 并回填输入框（现有回填逻辑已具备）。
- 发送期间：输入器加 `:has(:disabled)` 底色 + 提示文案改"正在发送…"，**不要**整块降透明度（用户可能有内容要保留）。
- 右栏：`plan-status` 胶囊同步临时显示"统计中/保存中"；分析运行中打开洞察 tab 显示"正在生成洞察…"，而不是错误引导文案。
- `pending` 期间真正被禁用的控件必须有禁用视觉：`opacity: .55; cursor: progress`。

### 2.4 结构变化规则

- **所有折叠/展开**统一走 `grid-template-rows: 0fr → 1fr`（`--duration-base`），常驻挂载 + `data-open`，关闭时 `inert`。适用于：条件编辑器、创建确认区、运行记录、Ask 卡退场、横幅。
- **所有浮层**统一：`--elevation-2` + `transform-origin` 指向触发点 + 140ms `opacity/translateY(4px)/scale(.98)` 进入（`@starting-style`）。
- **tab 切换**：2px accent 滑块指示条（`transform: translateX`，180ms）+ 内容区 `key` 包裹 120ms 淡入。右栏 tab 建议统一为 `role="tablist"`，与移动端一致。
- **右栏宽度**：`width` 过渡 220ms `--ease-enter`；`body.split-resizing` 与 `prefers-reduced-motion` 下必须 `transition: none`。
- **消息入场**：仅作用于挂载（`message.id` 稳定复用，流式更新不重放），180ms 淡入 + 6px 位移。

### 2.5 拖拽状态

左右分隔条共用一条语言：拖拽中手柄线变 accent 色、grip 实心、顶部浮现 `xxx px` 等宽数字徽标（`--elevation-2`），松开 120ms 淡出；键盘方向键调整同样短暂显示 800ms。`SplitHandle` 需把实时宽度提升为 rAF 节流的 state，顺带修正拖拽中 `aria-valuenow` 过期的问题。

### 2.6 可访问性底线

- 新增 `animation` 必须逐个补 `animation: none` 于 reduced-motion（现有全局兜底只关 `transition`，`index.css:1477-1482`）。
- 按下态、loading 不得移除已有的 accent 焦点环；分隔条焦点环需恢复（`index.css:1515` 目前是 `outline: none` + 浅灰底，违反本模块自己的焦点约定）。
- 进度动效必须绑定真实运行状态；turn 完成后不再保留循环动画。
- 流式追加的自动滚动保持 instant（rAF 合并），只有"回到最新消息"按钮使用平滑滚动。

## 三、跨栏协作：从"三块并排的界面"到"一台联动的机器"

三栏各自的反馈补齐之后，还剩下一个更高层的问题：**它们之间没有"接力"**。动作在一栏发起，结果在另一栏出现，中间没有任何来源、落点和状态的连接。以下路径已逐条核对源码：

- **左 → 中**：选择会话（`App.tsx:440-450`）、新建（`App.tsx:452-465`）、标签确认并发送（`App.tsx:467-484`）。
- **中 → 右**：方案变更跳转（`App.tsx:996-1000`）、洞察摘要展开、分析消息"编辑/继续分析"（`App.tsx:1015-1018`）。
- **右 → 中**：条件讨论/补充条件（`App.tsx:1036-1040`）、"回到方案核验"（`App.tsx:1071`）、保存核验/统计/创建触发新运行。
- **布局联动**：右栏开合与 tab 切换会改变中栏宽度（`workbench-insight.css:6,12`）；移动端四 tab 切换。

### X-1（P0）切换会话时左栏没有乐观选中，三栏一起"悬空"

- 位置：`App.tsx:735`（选中态由 `thread?.thread_id` 推导）、`App.tsx:440-450`（`select` 要等 `getThread` 返回才 `update`）、`App.tsx:763`（`aria-disabled` 无样式）。
- 现象：点击另一条会话后，0.3~3 秒内被点项毫无变化，中栏仍是旧会话、右栏仍是旧方案，也没有"正在打开"信号。慢网络下用户会连点，或怀疑自己点错了。
- 方案：`select` 立即写入 `pendingThreadId` 做乐观选中（浅底 + 左缘 2px accent 条 + 标题降透明度）；中栏消息区 `opacity: .6` + `aria-busy`，右栏内容淡出为骨架；`getThread` 返回后交叉淡化切换；失败则恢复选中并在左栏就地提示。顶栏文案改为"正在打开会话…"。

### X-2（P0/P1）后台事件擅自改写布局，用户对面板的所有权被剥夺

- `App.tsx:148`：切换库或会话时强制 `setRightTab("plan"); setRightPanelOpen(true)`——用户刚收起的右栏被重新拉开，正在看的洞察 tab 被重置。
- `App.tsx:257-261`：对话内生成分析消息时自动关闭右栏——可能打断用户正在阅读的方案。
- `App.tsx:262-270`：技能报告到达时自动切到洞察并打开面板——桌面尚可；移动端 `rightPanelVisible` 仍为 false（tab 停在对话），用户完全不知道报告已生成。
- 方案（布局所有权规则）：
  1. 后台事件不得改变用户显式设置的布局。记录 `layoutTouchedByUser`，用户手动开关或切 tab 后置 true；切换会话只重置内容，不重置布局。
  2. 需要提示"有新内容"时用徽标而不是抢布局：右栏开合按钮与"洞察"tab 上加 6px accent 点，并配 `role="status"` 文本（"有新的洞察报告"），打开即清除。
  3. 自动打开至多保留一种情形——技能报告到达且用户停留在对话、没有未读遮挡；打开时给出可撤销提示（"已打开洞察报告 · 收起"）。
  4. 自动关闭改为可恢复动作：关闭前记录来源，中栏对应分析卡上提供"在右栏查看"入口。

### X-3（P1）跨栏跳转没有来源，也没有落点

- `App.tsx:996-1000`"方案变更"跳转：只设置 `highlightedClauses`、打开右栏并聚焦编辑器，但**不把目标条件滚动到可视区**（`ClauseSummary.tsx` 只渲染 `data-highlighted`，无滚动逻辑）；高亮是浅蓝底 + 1px outline（`index.css:1505`），且 `highlightedClauses` 只有 setter、永不清理（`App.tsx:67`），高亮会一直驻留。
- `App.tsx:1071`"回到方案核验"：切回对话并把文本写进输入器，但输入器没有脉冲或滚动提示；移动端覆盖层直接消失。
- 方案（接力规则，三条同时满足）：
  1. **源反馈**：被点击的跨栏控件有 90ms 按下态；触发后 1.2 秒内显示微型回执（"已定位到方案"/"已填入对话"），不新开浮层。
  2. **落点反馈**：目标元素 600ms 高亮脉冲（`#eef5fd` 淡出至透明 + 左缘 2px accent 条），`scrollIntoView({ block: "nearest" })`，1.6 秒后自动清除，禁止永久高亮。
  3. **焦点转移**：`focus({ preventScroll: true })` 到目标控件；记录来源元素，Esc 或关闭面板时焦点回到来源，而不是永远回到顶栏按钮（`App.tsx:104-106`）。

### X-4（P1）同一个运行，三处状态词各说各话

- 顶栏（`App.tsx:669-675`）说"正在保存…/整理中"，右栏状态胶囊（`PlanPanel.tsx:63`）说"整理中/待处理/已核验"，中栏时间轴（`RunTimeline.tsx:89`）说"正在整理条件…"。同一时刻可见三套词汇，且右栏操作期间胶囊仍停在旧值。
- 方案：建立一张共享状态映射表，三处从同一处取文案；顶栏补充操作类型（打开会话/发送/统计/创建/保存核验），由 `operation()` 的调用方传入；运行中顶栏显示"阶段 + 进度"（如"整理条件 2/4"），点击顶栏状态跳到中栏时间轴。

### X-5（P1）右栏的错误出现在中栏，离操作点一屏远

- 右栏发起的统计/创建/反馈失败，错误只出现在中栏顶部 banner（`App.tsx:941-953`），右栏内部没有任何失败回执。
- 方案：就近回执——发起栏内联错误（带重试按钮），全局 banner 只做无法归属的兜底；banner 的"刷新状态"改为"回到出错的控件"（滚动 + 聚焦），因为整页刷新会丢掉用户上下文。

### X-6（P1）左栏标签到对话的交接没有阶段感

- "确认并梳理"（`App.tsx:1074-1090`）确认后，标签立即从左右两处清除、弹窗关闭，中栏输入器出现 chips，但没有任何"交接"信号。
- 方案：确认后左侧选中行先播放 800ms"已加入对话"状态（accent 底 + 对勾）再清除；中栏上下文标签行 400ms 脉冲一次并聚焦输入器；顶栏从"正在整理标签…"过渡到"已加入 N 个标签"。

### X-7（P2）移动端跨栏没有方向，返回时丢失位置

- 移动端四个 tab 是瞬时 `display` 切换（`index.css:1427-1456`）；从对话进入右栏覆盖层、再从右栏"在对话中讨论"回到对话，两个方向都是硬切；各面板的滚动位置也不保留（右栏切 tab 会重新挂载）。
- 方案：覆盖层按来源方向滑入/滑出（24px + 淡入，180ms，复用面板距离 token）；为每个面板记忆 `scrollTop`，切回时恢复；返回时聚焦来源控件。

### X-8（P2）宽度联动缺少"左右栏不能同时吃满"的规则

- 右栏在方案/洞察间切换宽度 370px → `clamp(370px, 44vw, 620px)`，中栏同帧重排；`splitMax` 能防重叠，但窗口变窄时只能靠 clamp 静默压缩。
- 方案：宽度变化统一 220ms；中心区将低于 420px 时自动收起左栏（IDE 式），顶栏给一次性提示"已收起侧栏以保持对话宽度"；双击分隔条恢复默认宽度。

### 跨栏动作 → 应有反馈链

| 动作 | 源反馈 | 过渡 | 落点反馈 | 失败回执 |
|---|---|---|---|---|
| 切换会话 | 左栏乐观选中 + 打开中态 | 中栏 120ms 交叉淡化 | 右栏骨架 → 内容 | 左栏恢复选中 + 内联错误 |
| 方案变更 · N 项 | 按下态 + "已定位"回执 | 右栏入场 200ms | 滚动到条件 + 600ms 脉冲 + 聚焦 | 目标不存在时轻提示 |
| 编辑/继续分析（中→右） | 引用块按下态 | tab 滑块 180ms | 报告内容 120ms 淡入 | 右栏内联错误 |
| 回到方案核验（右→中） | "正在回到对话…" | 移动端面板滑出 180ms | 输入器脉冲 + 聚焦 + 选区 | 中栏内联错误 |
| 标签确认并梳理（左→中） | 行内"已加入"800ms | 无 | chips 脉冲 400ms + 聚焦 | 弹窗内联错误 |
| 技能报告到达 | 右栏按钮/洞察 tab 徽标 | 不抢布局 | 打开时清除徽标 | 轻提示 |

### 新增设计原则（写入 DESIGN.md）

- **接力原则**：跨栏动作必须有源反馈、落点反馈与焦点转移，不允许"点了以后内容在别处悄悄出现"。
- **布局所有权**：后台事件只提示、不改写布局；用户显式开关优先。
- **单一状态源**：同一运行在顶栏、右栏、中栏使用同一份状态词汇与进度。
- **就近回执**：操作结果与错误出现在发起栏，全局区域只做汇总与跳转。

## 五、实施顺序（按"每批结束都能被用户感知"排序）

### 批次 0：立语言（纯 CSS，风险最低，收益最大）

1. 把 2.1 的 token 加进 `index.css :root`。
2. 落地 2.2 全局按下态 + 三条例外。
3. 修掉全局 hover 污染（会话项选中加深、运行记录标题局部圆角灰带）。

> 结束标志：任意按钮按下都有 1px 位移/缩放；慢放录屏可见按下帧。

### 批次 1：消灭"静默等待"（体感最强的可用性修复）

1. 发送乐观气泡 + 发送中提示 + Composer 禁用视觉（中栏 P0-2/3）。

> 结束标志：任何异步操作在 100ms 内有可见反应，且等待期间界面不会"假装可操作"；点击会话后旧内容不会继续冒充新内容。

1. **Elevation**：把"当前界面没有 box-shadow / 不要为普通面板增加无来源的投影"改为：
   *"静态内容面无投影；状态反馈用形变与状态色；瞬态浮层（下拉、菜单、弹窗、拖拽读数）与输入器使用 elevation-1/2/3。"*——这本来就是代码现状（`index.css:166`、`867`）。

## 七、验收标准

- 慢放 90ms 录屏点击任意按钮（顶栏/发送/统计/创建/菜单项），按下帧可见位移或缩放。
- 回车发送后 100ms 内出现乐观气泡；等待期间输入器显示"正在发送…"，不是看起来可编辑。
- 点击"统计人数"，按钮在 100ms 内出现 spinner 与"统计中…"，宽度不跳；状态胶囊同步。
- 右键/切换"洞察"tab：指示条滑动 180ms、内容 120ms 淡入、右栏宽度 220ms 过渡，无整页跳动。
- 拖动任一分隔条：线变 accent、grip 实心、顶部显示 `xxx px`，松手 120ms 后消失。
- 运行结束：时间轴不立即消失，先高亮标题，800ms 后收起。
- 系统开启"减少动态"：无位移、缩放与循环动画；颜色/边框/阴影状态仍在；菜单与折叠立即出现；spinner 与真实进行中状态保留。
- 键盘 Tab 走完全部控件，焦点环均为 accent 2px / 偏移 3px，分隔条不再例外。
- 点击历史会话后 100ms 内出现乐观选中与"正在打开会话…"，旧会话内容不会继续冒充新内容。
- 技能报告到达时，用户已关闭的右栏不会被强行打开；右栏按钮出现内容徽标，打开后清除；移动端在对话页也能看到该徽标。
- 点击"方案变更 · N 项"：右栏滚动到目标条件并高亮 600ms，1.6 秒后自动清除；按 Esc 或关闭面板后焦点回到发起按钮。
- 右栏发起统计失败时，错误显示在右栏按钮附近并可重试，中栏 banner 不是唯一出口。
- 同一运行进行中，顶栏、右栏状态胶囊、中栏时间轴显示的阶段词一致，顶栏可点击跳转到时间轴。
- 移动端从对话进入右栏、再回到对话，两个方向都有方向性过渡，且各自滚动位置被保留。
