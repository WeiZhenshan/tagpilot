# 对话式洞察 Agentic UI 实施记录

2026-10-21。把洞察从“选择技能后到右侧看报告”扩展为自然对话中的分析、图表和连续探索，保留圈选、显式 Skill 及旧报告入口。

## 使用方式

在工作台直接描述问题，无需先选 Skill 或标签。有已核验客群时继承当前范围，明确要求全量时使用当前标签库的授权全量；一句话可以要求先圈选再分析。未定义的高资产阈值、歧义指标、缺少范围或多个不明确图表，通过对话补充。

答复支持文字、图表、表格、澄清和状态。图表可以查看数据与来源、放大、导出，或“继续分析此图”将具体版本带入输入框。分类选择只准备后续分析，不立即查询。新结果留在新消息中，旧图不覆盖；刷新恢复同一证据。右侧按需展示本轮分析，主体结果在对话中。

## 调用链与授权

```
React intent=auto → Java核验线程/版本 → Python profile=conversation
  → route_request锁定圈选/分析/复合/视图/澄清
  → 已发布语义检索、原生Skill、受控分析请求
  → Java在已登录用户读取线程时执行声明式请求
  → 同批只读聚合、质量检查、证据登记、内容校验
  → 事务提交后的回执 → Agent继续 → 消息内容块/版本化图表
```

使用既有认证轮询/SSE读取作为分析中继，不新增未登录回调入口，不向模型注入用户令牌或数据库凭据。Python产生随机request_id和有效期；Java校验当前用户、线程归属、权限、发布身份后执行。回执保存在加密会话outbox，事务提交后发送，网络失败重传同一回执。Python按运行、owner、请求编号和摘要幂等接收。过期/取消后的请求不能解锁后续操作。

中继依赖已认证页面继续读取；短暂断线可重连继续，离开页面超过请求/整轮预算会中断，已核验内容仍保留。当前不提供离线后台无限续跑。

route_request是Agent内的路由工具，不访问业务数据。四个业务工具由Java控制：

| 工具 | 行为 |
| --- | --- |
| get_analysis_context | 读取当前范围、图表候选、证据和条件；图表引用只能选择当前会话内的合法版本 |
| query_aggregates | 当前客群/授权全量的声明式聚合，最多5标签、二维分类、12活动节点 |
| derive_facts | 服务端计算同口径差值及同查询的分子/总体人数比例 |
| submit_insight_result | 核验并发布内容块，可分次提交，最终提交结束本轮 |

复合请求的submit_result READY只完成圈选阶段，范围送Java核验后继续分析，不提前结束或创建实体客群。子集分析与原条件取交集，保留原圈选；明确的新圈选才更新当前方案版本。

## 证据、图表与持久化

- 单位、倍率和码值取自校验哈希的不可变发布快照，登记台未发布编辑不能改变口径。
- 聚合在同一短RR只读事务中重算活动计划，包括相关总体、对照与下钻；模型思考期间不保持数据库事务。
- 数据日期未知时明确记为未知，查询时间单独保存，不将元数据发布版本或执行日期当作业务数据快照。
- Java检查客户键唯一性、有效样本、缺失、单位、分类上限、小样本、互补格与关联范围的小差分；空客群、缺失和抑制分别处理。
- 模型只提交查询/事实引用，不提交SQL、物理列、任意图表配置或可信数值。正文数字绑定事实，派生计算由Java执行。
- 服务端从核验查询编译图表，前端继续运行chartGuard，导出使用同一事实表。新对话支持KPI、表格、条形、热力及完整互斥分类的堆叠构成；旧漏斗继续使用原受控报告链路。
- 方向、排序和条形图/表格切换复用证据，生成新图表版本，不重新取数。
- 无检验结果不能声称STAT，无规则证据不能声称RULE；因果、收益及仅凭均值/中位数推断完整分布形态均受到边界约束。

消息parts与analysis_artifacts[id@version]保存在既有ts_agent_thread加密payload中，独立于临时事件恢复，不需要数据库迁移。浏览器只收到展示证据，不收到内部会话、回执和完整查询计划。内容块、查询和会话图表数量均有界。

前端注册表只渲染平台组件，不执行模型HTML/JavaScript。历史消息继续读取text；显式Skill报告也附着到对应消息。滚动由是否仍在底部的状态控制，异步图表载入不抢走历史阅读位置。
