# 工作台处理记录流式展示优化

实现依据：用户上传的《流式输出优化.md》后半部分修订方案。

## 交互

- 四阶段计划：理解需求、匹配标签与口径、校验方案、整理结果；需求层由检索查询提前建立，再由意图台账接管。待办、进行中、完成和受阻分别展示。
- 工具动作按 `call_id` 配对，同类连续操作成组；展示业务对象、结果、授权标签名和耗时。
- 调用前的整句业务说明采用前端打字效果；追加事件每 180ms 展示一条。刷新与历史回放直接展示全文，减少动态效果偏好下立即展示。
- 运行中默认展开最新条目，结束后收起；等待业务选择时在记录内展开 Ask。取消、失败后的操作停止转圈。
- 方案变更可展开中文条件摘要，并定位、高亮右侧当前方案中的对应条件。自动滚动沿用 Assistant UI 的贴底跟随和“回到最新消息”。

## 事件与兼容

原字段保留；新增 `call_id / targets / requirement_ids / queries / depth / ok / summary / items / counts / duration_ms`。
`narration` 只保存整句，限 60 字，不保存 delta；工具候选名只取当前授权证据，最多 5 项。无新字段的旧会话仍可回放。

实际 SDK 0.1.50 会把一轮回复的 Text 和 ToolUse 拆为两条 AssistantMessage，因此在 SDK 适配器中暂存文本，收到随后工具调用时发出一次说明，在 UserMessage/ResultMessage 边界或提交后清空。单独收尾文字不会发出。工具调用与文字同消息、拆消息两种格式均可处理。

`thinking` 继续关闭；原有轮询接口和 Java 事件透传仍可使用。前端不依赖说明存在，工具对象描述是默认回退。检索中的聚合术语仅在展示摘要中清理，实际检索参数保持原意。
