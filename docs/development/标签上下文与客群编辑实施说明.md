# 标签上下文与客群编辑实施说明

本次依据《左侧加入标签列表自主选择上下文》方案及其末尾决定实施：每批最多 5 项、确认前可补充说明、仅智能体客群回跳，手工规则客群保留旧编辑器。沿用当前 Claude Agent SDK 单 Agent 和 Java 权威编译/执行边界。

## 交互

- 左栏「会话 / 标签」独立于当前会话；新建和历史会话均可使用。标签库跟随会话，切库新建草稿并清空已选标签和输入框 chip。
- 目录勾选其下全部可用标签，超过 5 项时按树顺序选至上限并明确提示剩余标签未选入；目录三态反映实际选择。搜索保留目录路径，只渲染展开节点。当前条件及计算表达式引用的标签显示「已在方案中」并禁止重复勾选。
- 「确认并让智能体梳理」打开补充说明弹窗，确认后用可见默认消息发起一轮运行。也可「加入输入框」，保留已输入草稿，补充文字后发送；仅 chip 也可发送。
- 运行中、WAITING、归档仍可浏览与选择，发送入口提示阻断原因。发送成功清空本轮 chip，失败保留选择、说明和草稿。用户消息持久化 `context_tags:[{id,name}]`，历史回显且进入后续 history。
- 所选标签是优先候选，不是强制使用或取值授权。仅选标签的新增叶子不得填入猜测阈值/码值；缺条件取值和组合关系通过现有 Ask/resume 逐轮确认，每轮最多 3 题。默认 AND 只能作为待确认草案结构，不能未经确认 READY。补充说明和后续回答仍经过已有 Guard、冻结条件及 Java 权威核验。

## 接口与权限

| 接口 | 行为 |
|---|---|
| `GET /taglibrary/agent/tags/tree?libraryId=…` | 要智能体查看权限和库可见性；上线树与当前发布资格求交集，剪去空目录，仅返回 id/tagId/label/tagType/dirPath/children，不暴露物理字段 |
| `POST /taglibrary/agent/threads/{id}/runs` | 新增可选 `context_tag_ids: number[]`、`context_only: boolean`；Java 校验数量、编号、库归属和当前资格，转换为内部 `pinned_tag_ids`、`pinned_only`，纳入幂等内容校验 |
| `POST /taglibrary/agent/threads/from-group {groupId}` | 要智能体查看、客群编辑及库可见性；保存规则 schemaVersion>=4 且含 audiencePlan.tree 才支持回灌 |
| `POST /taglibrary/agent/threads/{id}/create-group` | 普通会话仍要求 add 并 insert；带 source_group_id 的编辑会话要求 edit 并 update 原 groupId。名称、方案 revision/hash、条件完整性、最新版本和当前资格仍校验 |

树的读取和每轮发送分别重新取得资格，发布或字段状态变化不会因为浏览器已有选择而绕过校验。内部 Python 请求继续 `extra=forbid`，新字段有默认值，不破坏旧客户端。

## 客群编辑

列表返回 `agentEditable`，只表示有可回灌的保存方案；schema=3 手工规则不会转成智能体方案。智能体客群经 Vue iframe 透传 groupId，React 调用 from-group，并切换到实际所属标签库和左栏标签页。

先恢复本人未归档、来源客群和原规则摘要仍一致的编辑草稿；再次进入或刷新不会清空修改、运行或 Ask 进度。首次进入时，仅当本人未归档、空闲会话的当前方案与客群保存方案完全一致，且执行记录 plan_hash 一致时复用原会话。原会话删除、归档、属于他人、运行中或后续已改方案时，以客群保存的 audiencePlan 新建「编辑：客群名」会话，不读取他人对话。首次载入保存方案时标记无效草稿，清除旧人数和执行结果，显示重新核验入口；通过现有 edited_plan 核验后才能统计、更新。

React 初始化复用同一个请求 Promise，防止开发模式重放 effect 时重复创建编辑会话。对象群列表传入当前真实路由作为返回地址，并兼容旧 `/objectgroup/list` 链接到实际菜单 `/objectgroup/group`。

Java 持久化服务端保存的 `source_plan` 并注入内部运行请求，不采纳浏览器伪造的来源方案，同时恢复保存条件的既有确认状态。来源校验承认语义未改变的保存条件，以及用户点选的完整标签名与原样补充说明；新增或改值仍逐项校验。明确点选字段和发布码值不重复确认默认定义。右侧完整新增条件通过一次「确认新增条件」进入现有手工编辑核验；来源格式提示合并到此动作，数值漂移、缺值、资格与口径错误不会被隐藏。

编辑会话保存 source_group_id、原规则摘要和名称。更新事务锁定原客群，检查其仍存在、库未变化且规则/名称未被其他操作修改；冲突要求从列表重新进入。保留原客群描述与创建信息，重建规则和 SQL，人数只使用本版本统计结果，否则清零。更新仍以 thread/revision 唯一执行记录幂等，成功后界面显示「已更新客群」。
