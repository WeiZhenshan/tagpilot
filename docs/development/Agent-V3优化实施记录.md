## 实施前确认的限制

`workbench_graph.py` 固定绑定阶段条件 ID 集合；`plan.py` 与 Java 编译器只接受标签与常量比较；校验错误直接转为 Ask。全量表达、比例和条件计数没有独立执行节点。明细案例是否可执行必须以发布能力为依据，不能根据测试文件中存在明细说明就推断已接入。

## 契约方向

外部方案 `schema_version=3` 仍保留 `tree` 便于历史与界面兼容，新增 `intent_plan`、`diagnostics`、`plan_status`。叶子可以是现有标签、`DERIVED_PREDICATE` 或 `SCOPE_ALL`；派生表达只接受登记算子及已发布标签/能力引用。Java 编译为 `RulePayload.schemaVersion=4`，同时保存原发布方案并在对象群保存/统计/预览时重新编译，避免绕过发布校验或被旧编辑器有损保存。

能力记录随不可变发布快照导出，业务定义和聚合实现必须先复核。未发布能力不进入模型上下文；所有依赖标签均须属于当前资格集。表达式不接受模型提供的 SQL、字段、表名或函数名。

## 尚未生效或未覆盖的部分

- 本次修改了源代码、增加迁移和文档，未执行数据库迁移，未替换正在运行的Java/Agent/语义服务，未发布新业务能力或激活快照；当前运行环境不会因源代码修改而全部自动升级。
- 评分CASE、任意日期计算、多表JOIN、窗口函数、多层聚合不在当前白名单。J01–J03、I03/I04、F06等需要治理后的指标或后续受控扩展；逐项说明见61条能力矩阵。
- 聚合模板的FULL覆盖声明由业务复核负责；代码核验发布声明及数据来源，不能凭代码保证源明细完整。
- 语义库没有相应指标/已复核能力时保留CAPABILITY_GAP，不能为了通过案例造出标签或代理。
- A04约105秒；当前仍存在真实检索与多轮规划延迟，没有宣称达到响应时延目标。
- 前端构建仍有现有体积提示，Python依赖有弃用提示。Impeccable检查的单个旧Vue侧边框提示位于原样式，与本次新增状态布局无关；未扩大改动范围。
