## 修复 Agent 前端会话列表顺序随机打乱的问题

### 根因
`ruoyi-agentui/src/views/ChatView.vue` 中，点击切换会话（`selectSession`，L228-234）会先调用 `saveSession` 给**被切走的会话**盖上 `Date.now()` 时间戳并整表重排（L194 `sort`）。每次点击列表都重排：刚切走的会话置顶、正在看的沉底，来回切换时反复互换位置；加上 `Date.now()` 毫秒级精度导致同毫秒时间戳并列（稳定排序下保持排序前顺序，取决于操作历史），顺序看起来完全随机。

### 改动（全部在 ruoyi-agentui/src/views/ChatView.vue，共 3 处）

1. **核心修复**：`selectSession` 删除 `saveSession(sessionId.value, messages.value)` 调用（L230），切换会话变为纯视图切换。
   - 安全性：记录与消息数组共享同一引用（`saveSession` 存 `messages: msgs`，`send` 原地 push），消息始终同步；标题取自首条用户消息不变；记录创建/时间戳更新只发生在 `send()` 的 finally；空会话被 `if (!msgs.length) return` 拦截。

2. **时间戳单调化**：`saveSession`（L182）中新增模块级变量（如 `let lastTs = 0`），L188 的 `updatedAt: Date.now()` 改为 `updatedAt: Math.max(Date.now(), lastTs + 1)` 并同步 `lastTs`，消除同毫秒并列，排序完全确定。

3. **防御性兜底**：`groupedSessions`（L160）中 `Math.max(...items.map((s) => s.updatedAt || 0))`，旧数据缺 `updatedAt` 不再产生 NaN。

### 验证
- `cd ruoyi-agentui && npm run dev` 启动，后端（FastAPI :8000）运行。
- 新建多个会话并发送消息；反复点击切换会话，确认列表顺序在切换时不再变化，仅在对话流式结束后按最近更新置顶。
- 检查 localStorage 中 `agent_chat_sessions` 的持久化顺序与界面一致。
- 清理旧数据后（无 `updatedAt` 字段）验证分组排序正常。
