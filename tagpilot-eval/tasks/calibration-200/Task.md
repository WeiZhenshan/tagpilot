## 任务与完成条件

在标签库 107 当前可见事实与固定日期 2026-09-18 / Asia/Shanghai 下，客户经理提出一个圈选需求。理想 Agent 保留每一项明确要求，正确绑定标签、码值、单位与口径，按支持能力返回 READY、NEEDS_USER_INPUT 或 CAPABILITY_GAP。用户未确认前不执行建群；缺失字段或不明口径不允许降低条件。

本次交付验收是：冻结来源、审计 969 标签、交付 200 个母案例及四项契约、用独立解释器和 SQLite 检查可计算真值、生成待复核清单，并确保 P2 被拦截。**不是**被测 Agent 能力通过或银行口径验收。

## 任务文件与角色边界

- `data/calibration-v1/inputs.jsonl`：首轮公开输入与固定日期，不含标准答案。
- `data/calibration-v1/cases.jsonl`：私有标准条件树、目标与禁止标签、资格列表、终态、槽位、缺口、固定多轮话术、事实引用与谱系。
- `data/calibration-v1/oracle-results.jsonl`：私有完整模拟 ID 集，仅针对指定 SQL hash。
- `knowledge/WORLD.md`：通用规则，不包含任何题目的组合答案或人数。
- `data/p0-v1/manifest.json`：来源、代码 hash、活动版本及文件 hash；来源改变须新版本。
- `reports/p0-p1-v1/human-review-queue.jsonl`：分层抽检 40 题，默认 PENDING。

## 环境与公平性

本轮是离线工程校准，不调用模型和业务执行 API。SQL 仅被解析为确定性内存 fixture，不导入数据库。实时 P0 采集仅做元数据 SELECT 与健康/统计读取。

未来 Agent 运行只能获得输入与其资格允许的业务事实；不能读取评测控制面。多轮回复按预定义变更脚本逐轮给出，最多四轮，不根据错误临时补造用户需求。每次运行须记录代码、模型、prompt、快照、build、artifact、资格、日期、配置、耗时与成本。接口尚未接入，当前真实运行数为 0。

## 裁判与证据

1. L0 质量检查核验来源 hash、引用、码值前导零、字段单位、操作符、未解决事实与资格。
2. L2 条件树解释器独立于被测 Agent / Guard。允许同级 AND/OR 顺序变化、同逻辑扁平化和集合排序；不猜测未知等价变换。
3. 可计算轮次按 Decimal、日期和显式 NULL 排除规则运行全部 2,000 行仓库 fixture；检查完整排序 ID 集、hash 与数量。ID 全集为主，人数只是辅助。
4. 每个可计算轮次再用独立 SQLite 编译/查询交叉验证；SQL 来自测试参考树，绝不执行模型生成 SQL。
5. 边界覆盖阈值上下与相等、NULL、零、负数、日期端点、分母为零。错误绑定、漏条件、AND 改 OR、伪造 valid 和缺失证据分别失败或 RUN_INVALID。
6. 澄清和缺口题具有标准槽位/原因与禁止行为；当前不声称已实现自然语言问句自动评分。

`FIXTURE_ORACLE_AVAILABLE` 只表示存在离线真值，不能解释为真实 Java 执行通过。无可计算标准树的题不计入执行通过分母。9 个事实冲突以缺口暴露，禁止自动猜测累计/最高等口径。
